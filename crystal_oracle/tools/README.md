# Crystal Oracle asset tools

`build_assets.py` turns the owner's raw material (ChatGPT pictures, voice
recordings, sounds) into the files the Crystal Oracle screen plays from its TF
card. It reads `assets/manifest.json` (schema: `assets/manifest.schema.md`) and
writes `sd_card/oracle/…`:

* clips: animated **OMJ1** files, or 800×480 JPEG stills;
* sounds: WAV files, 48 kHz mono 16-bit;
* `captions.ini` (the words, plus the lantern-glow anchor of every clip), a `config.ini` template, and a `README.txt` for the card;
* contact sheets of the clips in `assets\previews` (open `index.html`), so you can check the animation without the screen.

It only rebuilds what changed. It can fill gaps with placeholders: labelled
test clips, synthesized sound effects, and voice lines spoken by Windows' built-in voice.

## Requirements

* **Python 3** (tested with 3.14). The standard library is enough; nothing to `pip install`.
* **ffmpeg + ffprobe** on PATH (tested with 8.1.1). To install: `winget install Gyan.FFmpeg`, then open a new terminal.
* **Windows** for the TTS voice placeholders (System.Speech, built in).
  Everything else also works on macOS and Linux.

Run every command from the `crystal_oracle` folder (the one that contains
`assets`, `firmware` and `tools`). The `-I` flag is deliberate: it makes Python
ignore stray modules in the current folder.

```
python -I tools\build_assets.py --check
```

## First time

1. `assets\manifest.json` is the DRAGONGLOW story manifest (STORY.md). It lists
   every picture, clip, voice line, sound effect and the on-screen words. It is
   generated by `tools\gen_manifest_dragonglow.py` (re-running that script
   overwrites hand edits, so make lasting changes there). The archived Moonshards
   manifest is `docs\stories\manifest.moonshards.json` (its old generator,
   `tools\gen_manifest_from_story.py`, also writes `assets\manifest.json`).
   `assets\manifest.example.json` is a small example of the older recipes.
2. `python -I tools\build_assets.py --check` validates the manifest. It writes
   **`assets\ASSET-STATUS.md`**: what exists, what's missing, and what the
   station will show for each cue (MVP items first).
3. `python -I tools\build_assets.py --placeholders --test-clips` builds a card
   that already works end to end. Test cards, synth sounds and a computer voice stand in for missing assets.
4. Copy **`sd_card\oracle`** to the **root** of the TF card (FAT32), so the card
   has `\oracle\clips`, `\oracle\voice` …
   * On a card already in use, answer **Skip** for `config.ini`: the card's copy
     may hold settings changed in the service menu.
   * Keep `\oracle\state` and `\oracle\logs` on the card; they hold the station's counters and logs.

## Everyday use: adding real assets

| you have | put it here (the name must match the manifest id) |
|---|---|
| a ChatGPT picture for still `bg_window` | `assets\source\images\bg_window.png` (`.jpg`, `.jpeg` and `.webp` also work) |
| a voice line `greet_r2_1` | `assets\source\voice\greet_r2_1.mp3` (`.wav`, `.m4a`, `.ogg`, `.flac` and `.aac` also work) |
| a sound effect `absorb` | `assets\source\sfx\absorb.wav` (or any of the audio types above) |
| a music bed `idle` | `assets\source\music\idle.mp3` |
| a video for a `video` recipe | `assets\source\video\<the file named in the manifest>` |

Then run `python -I tools\build_assets.py` again. Only the outputs whose inputs
changed are rebuilt. A real file always replaces its placeholder, and a still
replaces a test-card clip. Open `assets\previews\index.html` to look at the
clips (each one as four frames, with a cyan ring where the lantern glow will
be). Copy `sd_card\oracle` to the card again.

A `layers` clip is built as soon as its background and its required stills
exist; layers marked `"optional"` are left out until their still exists, and a
layer's `"fallback"` still stands in for a missing one. So the first clips
appear as soon as `bg_cave` and a Butterscotch picture are in `assets\source\images`.

Tips for the pictures:

* Keep the bottom quarter of every picture dark and empty: the screen draws words, numbers and the meter there.
* Use calm, smooth art. Grain and fine texture make big, slow frames.
* For sprites, mark the still `"transparent": true`.
  * A PNG with real transparency is used as is.
  * If ChatGPT gave you a flat green (#00FF00) or flat black background instead,
    the tool sees it in the picture's corners and keys it out automatically. For
    any other flat colour, set `"key": "#RRGGBB"` on the still.
* The character glow (the clip's "lantern" anchor) is placed from the still's
  `"anchor": [x, y]` (fractions of the picture, e.g. `[0.5, 0.62]`). If the cyan ring in the previews misses the
  glow point (Butterscotch's chest), adjust that still's `anchor` and build again.
* Backgrounds are cropped to 5:3 (800×480). Use `"crop": "top"` or `"bottom"` on a still to keep that edge.

## Voice lines with ElevenLabs: `make_voice_elevenlabs.py`

Records every voice line of `assets\manifest.json` with one ElevenLabs voice and saves it as
`assets\source\voice\<line id>.mp3`; the next `build_assets.py` run converts them (and pitches up the
`"fx": "smudge"` lines). Python standard library only; it talks to `https://api.elevenlabs.io/v1`.

* **API key:** the key alone in `tools\.elevenlabs_key` (git-ignored), or the environment variable
  `ELEVENLABS_API_KEY`. Never commit it or paste it into a chat.
* **Remembered choices:** the voice, model and voice settings of the last run are kept in
  `tools\.elevenlabs_voice.json` (no secret in it), so re-takes of single lines sound the same.
* **Skips** lines that already have a source file in `assets\source\voice` (any audio type); `--force`
  re-records them. A hand-made non-MP3 file that gets re-recorded is kept as `<name>.old`.

```
python -I tools\make_voice_elevenlabs.py --list-voices                                   # voices in your account
python -I tools\make_voice_elevenlabs.py --voice "<name or id>" --only attract_call_1 --force   # try one line
python -I tools\make_voice_elevenlabs.py --priority MVP                                  # the night-one set (voice remembered)
python -I tools\make_voice_elevenlabs.py                                                 # everything still missing
python -I tools\build_assets.py --placeholders                                           # convert + build the card
```

| option | what it does |
|---|---|
| `--list-voices` | list the voices in your account (id, name, category, labels) and stop. Library voices must be added to *My Voices* first |
| `--voice NAME` | voice name (exact, or a unique part of it) or voice id; remembered |
| `--model ID` | model id (default `eleven_multilingual_v2`); remembered |
| `--stability`, `--similarity`, `--style`, `--speed` | voice settings (defaults 0.40 / 0.75 / 0.30 / 1.07, after `STORY.md`'s voice direction); remembered |
| `--priority MVP\|NICE\|all` | which lines (default all) |
| `--only ID,ID` | just these line ids |
| `--force` | re-record lines that already have a source file |
| `--dry-run` | list what would be recorded and the character count (≈ credits); no key needed |

HTTP 429/5xx answers are retried with a growing pause. Alternative: in a fresh Claude session with the
claude.ai **ElevenLabs connector**, Claude can make the lines through the connector; save each as
`assets\source\voice\<line id>.mp3` and build as usual.

## Stills through Codex (ChatGPT plan): `make_image_codex.py`

Generates a still with ChatGPT's image model by driving the **Codex CLI** non-interactively, so it uses the
ChatGPT plan's Codex limits, not API credits, and needs nobody at the keyboard. Python standard library only.

Setup (once): install the **Codex** app from the Microsoft Store and sign in with ChatGPT. The CLI is
`codex.exe` inside the app package (not on PATH); the script finds it with `Get-AppxPackage OpenAI.Codex`
on every run (the folder name changes with each app update), or set `CODEX_EXE`.

```powershell
python -I tools\make_image_codex.py run --id prop_lantern "a glowing candy lantern on a mossy rock"   # wait (~3-8 min)
python -I tools\make_image_codex.py run --id bg_cave --force --ref bg_cave_lit "..."                 # re-take, style ref
python -I tools\make_image_codex.py start --id prop_lantern "..."   # detached: prints the job id, returns at once
python -I tools\make_image_codex.py status [job id]                 # all jobs, or one
python -I tools\make_image_codex.py wait <job id>                   # block until it ends (exit 0 = done)
```

| option | meaning |
|---|---|
| `--id ID` | install the result as `assets/source/images/<id>.png` (else it stays in the job folder) |
| `--force` | replace an existing still; the old file is kept as `<name>.old` |
| `--ref X` | reference image(s) for style/character: a still id or a file path (repeatable) |
| `--raw` | don't prepend the house style line (landscape for 800x480, storybook, no text) |
| `--any-shape` | accept portrait/square results (default: landscape only) |
| `--timeout S` | kill Codex after S seconds (default 1200) |

**Jobs.** Each job gets its own folder `assets/.codex_jobs/<time>-<id>-<rand>/` (git-ignored) with
`prompt.txt`, `prompt_sent.txt`, `codex.log`, `last.txt`, `job.json` and copies of the image(s). `job.json`
records the state (`queued` / `running` / `done` / `failed`), the worker and Codex PIDs, the Codex session id
and every image's format and size. `status` reports a job whose worker process has disappeared (for example
after a reboot) as `died`.

**How it works (and why).** Codex runs with the settings that were proven to work on 2026-10-23:
`codex exec --skip-git-repo-check --ephemeral -s workspace-write -C <job dir> -o last.txt -` with the prompt
on **stdin**. (`-i` takes several files, so it would swallow a positional prompt.) Codex's own file tools
time out in that sandbox, so it is told not to save anything. Codex always writes its images to
`~\.codex\generated_images\<session id>\`. The script reads the session id from `codex.log` and collects
**only that folder**, so parallel jobs never mix. Each image's header is checked: PNG/JPEG/WebP, width and
height, at least 512 px, landscape unless `--any-shape`. `build_assets.py` does the 800x480 fit as for any
other still.

## Options

| option | what it does |
|---|---|
| *(none)* | build everything that changed |
| `--check` | validate only and write `assets\ASSET-STATUS.md`. Also checks that the screen and plinth copies of `crystal_link.h` are identical, and that `settings.cpp`/`settings.h` agree. Exit code 1 if there are errors |
| `--placeholders` | missing voice lines → Windows TTS (cached in `assets\.cache\tts`); missing sfx/music → synthesized sounds |
| `--test-clips` | missing clips → labelled animated test cards. Each shows the clip id, "TEST CLIP" and a frame counter at the clip's fps; they are 3 s and loop |
| `--gen-defaults` | rewrite `firmware\crystal_oracle\story_defaults.h` from the manifest words, then rebuild the firmware. Builds nothing. `--defaults-out FILE` writes elsewhere |
| `--previews` | rewrite **every** clip's contact sheet in `assets\previews` (a normal build already writes the sheets of the clips that changed). On an up-to-date card it does only that |
| `--no-previews` | don't write contact sheets |
| `--only ID,ID,...` | build only these ids. Globs work (`reveal_t*`). Use `clip:`, `voice:`, `sfx:`, `music:` or `still:` to narrow by kind. A still id selects every clip that uses it |
| `--clean` | delete everything generated under `sd_card\oracle` (clips, voice, sfx, music, `captions.ini`, `README.txt`) and the build cache, then build. `config.ini` is never touched |
| `-j N` | parallel ffmpeg jobs (default 4) |
| `--dry-run` | show what would be built and why; write nothing |
| `--force` | rebuild even what is up to date |
| `--tts-voice NAME` | placeholder voice: part of an installed voice name, e.g. `Zira`. Default: `voice_style.tts_voice` in the manifest, then "David", then any |
| `--tts-rate N` | placeholder speech rate, −10…10 (default −1) |
| `--manifest`, `--assets`, `--out`, `--firmware` | other locations (defaults: `assets\manifest.json`, `assets`, `sd_card`, `firmware`) |
| `--ffmpeg`, `--ffprobe` | paths to the ffmpeg executables, if they are not on PATH |
| `-v` | print warnings, notes and every ffmpeg command |

## What gets generated (for `.gitignore`)

| path | what | commit? |
|---|---|---|
| `sd_card/` | the whole card image (clips, sounds, ini files) | no: generated, and big |
| `assets/.build_cache.json` | input hashes for incremental builds | no |
| `assets/.cache/` | TTS cache | no |
| `assets/previews/` | contact sheets of the built clips + `index.html` | no (`assets/.gitignore` already lists it) |
| `assets/ASSET-STATUS.md` | status report, rewritten on every run | optional |
| `tools/__pycache__/` | Python bytecode | no |
| `firmware/crystal_oracle/story_defaults.h` | only rewritten by `--gen-defaults` | **yes** (it's firmware source) |
| `assets/source/**` | your real pictures, voice and sounds | your call: large binaries |
| `tools/.elevenlabs_key` | your ElevenLabs API key (`make_voice_elevenlabs.py`) | **never** (git-ignored) |
| `tools/.elevenlabs_voice.json` | the chosen ElevenLabs voice, model and settings | optional (no secret in it) |
| `assets/.codex_jobs/` | `make_image_codex.py` job folders (logs, prompts, image copies) | no (git-ignored) |

## How it builds things

* **Clips.** Each recipe becomes an ffmpeg filter graph:
  * `still`: one picture.
  * `kenburns`: zoom and pan on a 3× canvas.
  * `float`: a sprite bobbing over a background. The loop is exact.
  * `crossfade`: exact-frame fades, with optional looping and bobbing.
  * `video`: crop, denoise, and an optional loop crossfade.
  * `layers` (`co_layers.py`, used by the whole story manifest): a timeline of
    stills over a background. Every stream is re-timed to pts = frame number,
    so frame *n* is exactly t = n / fps everywhere. Each sprite is decoded,
    keyed, scaled and tinted **once**, then repeated with the `loop` filter;
    per-frame work is only the animated parts (`fade` alpha, `rotate` with
    transparent corners, `scale` with `eval=frame` for animated height / spin /
    flutter) and the `overlay` with `enable=between(t,…)` and `eval=frame`
    position expressions. The background gets `zoompan` (zoom) and/or `rotate`
    (on a larger copy). `screen` layers are drawn on black and merged with
    `blend=all_mode=screen`. Colour variants are separate clips, one per
    crystal colour the words define (`awaken_1..3` today). A `tint` is a colour
    spec: `#RRGGBB` multiplies the sprite (`colorchannelmixer`); 2-4 stops
    `#RRGGBB,#RRGGBB` or `rainbow` multiply it by a gradient across the sprite
    box, mostly top to bottom with a slight diagonal (`geq` on planar RGBA,
    alpha copied through), like the colour bands of a gradient-filament print.

  The graph outputs baseline MJPEG (yuvj420p 4:2:0, `-q:v`, `+bitexact`). Graphs
  longer than ~24 000 characters go to ffmpeg through a file (`-/filter_complex`). Python
  then checks **every frame**: SOF0, 8-bit, 3 components, 2×2/1×1/1×1 sampling,
  800×480, one scan, its own tables. The frames are packed into OMJ1 (see
  `omj.py`). A frame over 96 KB triggers an automatic re-encode at q+2, up to q=12.
* **Audio:**
  * mono downmix, 120 Hz high-pass, then loudness normalisation (voice/sfx −16 LUFS, music −20 LUFS, true peak −1.5);
  * 5 ms fades, 48 kHz s16le;
  * `+bitexact`, so the header is the clean 44-byte one; every header is then checked byte by byte;
  * voice lines also get silent edges trimmed and a gentle compressor;
  * a voice line with `"fx": "smudge"` is pitched up 5 semitones at a net 1.15×
    speed first (`asetrate` + `aresample` + `atempo`), real recording or TTS alike.
* **captions.ini** comes from the manifest `words`, and is rewritten on every build.
  An `[anchor]` section follows: `<clip id> = x,y,r`, the lantern glow (screen
  pixels + radius) of every clip that has an `anchor_layer` and was built from
  real art (see the schema, `layers` → *Anchors*).
* **Previews**: `assets\previews\<id>.jpg` for every clip built from real art,
  a 2×2 sheet of the frames at 10/35/60/85 % (half size) with the anchor ring, and
  `index.html`. Only sheets whose clip or anchor changed are redrawn.
* **config.ini** is created only when `sd_card\oracle\config.ini` does not exist.
  * Its keys and notes come from the firmware's own table in `settings.cpp`; its values are the defaults in `settings.h`.
  * So it always matches the firmware. Delete it to get a fresh template.
* **Incremental builds:**
  * Each output's inputs are hashed into `assets\.build_cache.json`: the manifest
    entry, the source file contents, and the tool's recipe revision.
  * When a recipe changes in the code, bump `CLIP_REV` / `AUDIO_REV` in
    `co_media.py`; only those outputs rebuild.

`omj.py` also works on its own:
`python -I tools\omj.py info sd_card\oracle\clips\attract.omj` prints the
frames, fps and max/avg frame size, plus any problem the firmware would reject.

Files:

* `build_assets.py`: the command line, jobs and cache.
* `co_manifest.py`: validation and the `cues.h` names.
* `co_media.py`: ffmpeg recipes, colour keying and the WAV check.
* `co_layers.py`: the `layers` recipe: validation, fallbacks, the filter graph, anchors, the loop-seam check.
* `co_preview.py`: the contact sheets in `assets\previews`.
* `co_synth.py`: placeholder sounds and TTS.
* `co_firmware.py`: `config.ini`, `captions.ini`, `story_defaults.h` and the card README.
* `co_status.py`: `ASSET-STATUS.md`.
* `omj.py`: OMJ1 and JPEG checks.
* `gen_asset_list.py`: writes `CHATGPT-ASSETS.md` (the owner's list of pictures, lines and sounds) from the manifest.
* `gen_manifest_dragonglow.py`: writes `assets\manifest.json` for the Dragonglow story (every prompt, clip, line and word,
  including the no-button `nobutton.*` words). Re-run it, then `build_assets.py --gen-defaults` and `gen_asset_list.py`.
* `make_voice_elevenlabs.py`: records the voice lines with ElevenLabs into `assets\source\voice` (see above).
* `gen_manifest_from_story.py`: the one-off script that wrote the first `assets\manifest.json`; kept as documentation. Running it again overwrites the hand-edited manifest.

## Troubleshooting

| symptom | fix |
|---|---|
| `ffmpeg not found` | install it (`winget install Gyan.FFmpeg`) and open a new terminal, or pass `--ffmpeg C:\path\to\ffmpeg.exe` |
| `manifest not found` | copy `assets\manifest.example.json` to `assets\manifest.json` |
| `invalid JSON at line N column M` | usually a missing or extra comma or quote near that spot. JSON allows no comments and no trailing commas |
| `N manifest error(s) - nothing built` | run `--check`. Every error names the entry, e.g. `clips[attract]: 'image' = 'bg_windw' is not a still id` |
| a clip is still a **test card** although the picture exists | the file name must equal the still id (`bg_window.png` for `"bg_window"`). `ASSET-STATUS.md` shows **missing** next to each input it can't find |
| `biggest frame is … KB even at q=12` | the art is too busy (grain, noise, fine texture). Use smoother art, a shorter or calmer clip, or `"denoise": "6:4:10:8"` for video |
| `not loop-exact` warning | make `seconds` a whole number of bob periods, and `period × fps` a whole number (at 13 fps: periods of 1, 2, 3 s …) |
| a sprite shows as a **box** | set `"transparent": true` on the still. Green and black backdrops are keyed automatically; for any other colour set `"key": "#RRGGBB"` |
| a green fringe around a sprite | ChatGPT's green wasn't flat. Ask it for real transparency, or set `"key"` to the exact backdrop colour |
| the lantern glow is off the lantern | adjust the still's `"anchor": [x, y]` (fractions of the picture) and look at `assets\previews` again |
| a clip still shows the built-in animation | one of its required stills is missing: `ASSET-STATUS.md` lists the clip's inputs. Layers marked `optional` never block a clip |
| a sprite has holes where it is black | auto-keying removed the black. Ask ChatGPT for real transparency or a green background, or set `"key": false` |
| voice lines take too long on the device | trim them. The tool already removes silent edges; real recordings should be short (under ~3 s) |
| the TTS placeholder fails | it needs Windows PowerShell 5.1 (`powershell.exe`). Check the installed voices under Settings > Time & language > Speech; `--tts-voice Zira` picks another one |
| `crystal_link.h ... differ` | the screen and plinth copies must be byte-identical. Copy one over the other and bump `LINK_VERSION` |
| my edits to `captions.ini` on the card disappeared | it is regenerated from the manifest `words`. Edit the manifest (and run `--gen-defaults` if the firmware's built-in words should change too) |
| `config.ini` didn't pick up a new firmware setting | it is never overwritten. Delete `sd_card\oracle\config.ini` and build again to get a fresh template, then re-apply your changes |
| old clips or sounds still play | a build deletes the placeholders it made itself (TTS / synth / test cards) once the manifest no longer lists them, but real files deleted from the manifest stay in `sd_card\oracle` and on the card. Use `--clean`, and delete `\oracle\clips`, `voice`, `sfx` and `music` on the card before copying |
| odd characters in the console | harmless: the Windows console can't show some characters. The files themselves are UTF-8 |
