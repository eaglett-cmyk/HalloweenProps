# `assets/manifest.json` schema (schema 1)

The manifest is the single source of truth for everything on the TF card: the
pictures you make in ChatGPT (**stills**), the animations built from them
(**clips**), the voice lines, the sound effects, the music and every on-screen
word. `tools/build_assets.py` reads it, checks it against the firmware
(`firmware/crystal_oracle/cues.h`, `settings.cpp`/`settings.h`,
`story_defaults.h`) and builds `sd_card/oracle/…`.

`assets/manifest.json` is the DRAGONGLOW story manifest, generated by
`tools/gen_manifest_dragonglow.py` (re-running that script overwrites hand
edits). The archived Moonshards manifest is `docs/stories/manifest.moonshards.json`.
`assets/manifest.example.json` is a small but complete example of the five older recipes. Run `python -I tools\build_assets.py --check`
after every edit.

* The file is JSON in UTF-8, without comments. Use a `"notes"` field for comments.
* Any field named `desc`, `notes`, `note`, `comment` or `prompt` is free text,
  as is any field starting with `_`. The tool never interprets them.
* The check flags any other unknown field as "typo?".
* `--check` sorts its findings into three levels:
  * **ERROR**: the build refuses to run.
  * **warning**: the build runs, but something is probably wrong.
  * **note**: for information only.

---

## Ids

Every `id` becomes a file name on the card, and the firmware lower-cases names.

* Use only lowercase letters, digits and `_`, starting with a letter or digit, at most 40 characters.
* Ids must be unique within their own list. A sound effect and a clip may share
  an id: they go to different folders.
* `--check` warns when an id is one the firmware never asks for (`cues.h`).
  That check catches spelling mistakes such as `atract`.

## `words` → `/oracle/captions.ini` (and `story_defaults.h`)

`"section.key": "text"`. A key with no dot (`title`, `character`) is top-level.

* **Format:** lowercase keys; one section level (`caption.reveal_t0` = section
  `caption`, key `reveal_t0`); each value is one line. The one exception is the
  no-button prefix: `nobutton.caption.charge` = section `nobutton`, key
  `caption.charge` (the section is always the text before the **first** dot; see
  *No big button* below).
* **Colour keys:** a key ending in `_color` or `_hex` must be `#RRGGBB`, except the
  crystal colours `color.N_hex`, which take a **colour spec** (below).
* **Shape keys:** a key ending in `_shape` must be `circle`, `triangle` or `star`.
* **Captions:** keep `caption.*` values to about 24 characters, which is what the caption band fits.
* **Non-ASCII:** characters such as `…`, `é` or `✦` raise a warning, because the
  screen fonts may not have them. Write `...` instead of `…`.
* **Quoting:** the build adds the quotes for you.
  * A value with leading or trailing blanks, or with ` ;` inside, is written in
    quotes in `captions.ini`, because the firmware's INI reader would otherwise
    trim it or cut it at the comment.
  * A value that needs quotes **and** contains both `"` and `'` is an error.
* **Missing keys:** any key the manifest doesn't give falls back to the
  firmware's built-in words (`story_defaults.h`). `--check` lists the differences.

| key | meaning |
|---|---|
| `title`, `character` | show title, the narrator's name |
| `rank.1` … `rank.7` | rank names by total visits (1, 2, 3, 4, 5, 6–7, 8+) |
| `tier.0` … `tier.3` (+ `tier.N_color`) | trick, treat, rare, legendary |
| `bowl.common` / `rare` / `legend` (+ `_color`, `_shape`) | bowl names, colours, icon shapes |
| `color.1` … `color.6` (+ `color.N_hex`) | crystal colour names and colour specs (see *Crystal colours*). N = the colour id the bench writes to the tag (page 17 byte 1) |
| `caption.<cue>` | short caption per cue (`attract`, `awaken`, `greet`, `charge`, `reveal_t0..3`, `replay`, `nocrystal`, `foreign`, `sleepy`, `goodbye`, `milestone`, `circle`, `keeper`, `chapter`, …) |
| `ui.*` | fixed interface words (`place`, `hold`, `power`, `counter`, `press`, `or_press`, `touch`, `tonight`, `reader_asleep`, `rush`, `no_card`) |
| `meter.*`, `fx.*`, `glow.idle_color` | story features drawn by the firmware: the communal meter, device effects per visual, the idle anchor-glow colour (see *Story features* below) |
| `nobutton.<key>`, `nobutton.voice` | used instead of `<key>` / to swap voice lines when the plinth has **no big button** (`config.ini [station] button = no`, the default; see *No big button* below) |

`--gen-defaults` writes these words into `firmware/crystal_oracle/story_defaults.h`.
Rebuild the firmware afterwards, so a card without `captions.ini` shows the same words.

### Crystal colours (`color.N`, `color.N_hex`)

`color.N` is the name Butterscotch and the captions use; `color.N_hex` is its
**colour spec**, one of:

| spec | example | on the device | as a clip `tint` |
|---|---|---|---|
| `#RRGGBB` | `#5CD6FF` | a steady colour | a flat multiply-tint |
| 2–4 stops `#RRGGBB,#RRGGBB[,#RRGGBB[,#RRGGBB]]` | `#A35CFF,#2F7BFF` | the stops blend smoothly round and round, about 4 s per full cycle (a gradient filament); the plinth ring crossfades a 2-stop colour (`LED_DUAL`) | a gradient across the sprite box, first stop at the top, last at the bottom (with a slight diagonal) |
| `rainbow` | `rainbow` | the full hue wheel, about 4 s per turn; the ring drifts through the rainbow | a candy rainbow gradient (pink, orange, yellow, green, sky, violet) top to bottom |

* Write the stops with commas and **no blanks**; `rainbow` in lowercase. `--check`
  reports anything else (a bad `#RRGGBB`, an empty stop such as a trailing comma,
  more than 4 stops, blanks) as an ERROR. (The firmware is more forgiving, but the check keeps the
  manifest in the one form every tool reads.)
* **How many colours there are:** the highest N (1…6) with a non-empty
  `color.N_hex`, counting from 1 without gaps. Leave the unused ids out (or
  empty): Dragonglow defines 1 Moonspell `#A35CFF,#2F7BFF`, 2 Starfrost `#5CD6FF`,
  3 Rainbow Fizz `rainbow`, and ids 4–6 are free for future filaments. `--check`
  warns about a colour after a gap (never used), a number outside 1…6, a
  colour without a name, and a name without a colour.
* The colour count also decides which `variants: "colors"` clips are built
  (`awaken_1` … `awaken_<count>`) and which `awaken_b_<n>` voice lines can play:
  `--check` warns about an `awaken_b_<n>` above the count and about a defined
  colour with no `awaken_b` line.
* A crystal whose tag has no colour, or an id the words don't define, still glows
  in one of the defined colours (picked from its UID) but is never named: no `awaken_b`
  line and no colour-name caption at absorb.

### Story features (`meter.*`, `fx.*`, `glow.*`)

The firmware is story-neutral: these words decide what it draws for the story
(`docs/DESIGN.md` §5.6 explains the behaviour). `--check` reports a malformed
value as an ERROR. A key the manifest leaves out falls back to `story_defaults.h`,
then to the built-in default in the last column (the Moonshards look).

| key | value | meaning | default |
|---|---|---|---|
| `meter.style` | `moon` \| `lantern` | `moon`: a pale Moon drawn in the sky, a crescent filling to a full disc. `lantern`: a warm additive glow over a lantern **painted into the art** (a faint ember growing to a blaze, a gentle candle flicker, slow rising sparks); the device draws no lantern shape | `moon` |
| `meter.pos` | `x,y,r` | screen px: the Moon's centre and radius, or the painted lantern globe's centre and the glow radius at full blaze. Fix it after the art exists (look at `assets/previews/`). The station counter goes under it; the RECALL icon goes in the top corner away from it. Empty or not understood = the style's own spot | `650,110,46` (moon), `150,110,70` (lantern) |
| `meter.color` | `#RRGGBB` | the Moon / glow colour (also the finale bursts) | `#E9EEFF` (moon), `#FFB347` (lantern) |
| `meter.name` | text | the meter's name in the host menu ("Fill the Lantern", "Reset Lantern"), the Tonight page and the boot screen | `Moon` (moon), `Lantern` (lantern) |
| `meter.on` | comma list of visual ids | the visuals that show the meter (and, in `attract`, the counter under it). An id covers its `_` variants: `greet` = `greet`, `greet_r5` …; `attract` = `attract`, `attract_full`; `reveal_t0` = `reveal_t0_1..3`. It is matched against the clip/still on screen, or the step's own id (`recall_t1`, `reveal_t2` …) when there is no art. List only scenes where the meter is painted / belongs | the Moonshards window scenes: `attract,absorb,greet,recall,charge,reveal_t0,reveal_t1,replay,nocrystal,foreign,sleepy,goodbye,chapter_a,chapter_f` |
| `meter.zoom_<visual id>` | `from,to` (0.5–4) | that clip's background zooms about the centre from → to over the clip (the `layers` recipe's `bg.zoom`): the meter moves and grows with the painted spot. `gen_manifest_dragonglow.py` writes it for every `meter.on` clip with a zooming background (`meter.zoom_keeper = 1,1.15`) | none (no zoom) |
| `fx.<visual id>` | effects, `;`-separated | device effects on a visual: `kind,x,y,startMs,endMs[,jx,jy][,#RRGGBB]`. Times are ms since the step started. `poof` = a white puff (a flash and soft puffs over ~0.5 s, or end − start if longer) with a few sparkles, at start; `sparkles` = 3 sparkles every 120 ms around (x, y) ± jx/jy px (default 14/10) from start until end; `burst` = one 28-sparkle burst at start; `none` = nothing. Colour: the kid's crystal colour (poof: white) unless `#RRGGBB` is given. Looked up as `fx.<visual on screen>`, then `fx.<step id>_<variant>` (so `fx.reveal_t0_2` plays for gag 2 even before its clip exists), then `fx.<step id>`. **No key = no effects** | none |
| `glow.idle_color` | `#RRGGBB` | the narrator's voice-pulsed anchor glow (Oona's lantern, Butterscotch's tummy) when no crystal is on the stone | `#CFFFF2` |

The puff that hides the GLOW number on a trick result takes the trick tier's colour (`tier.0_color`).

Examples (Dragonglow): `fx.reveal_t0_1 = poof,615,230,1100,1100` (the rubber
chicken turns into a coin), `fx.reveal_t0_2 = sparkles,440,170,600,1800`
(hiccup sparkles from his mouth), `fx.reveal_t0_3 = burst,420,150,1420,1420`
(the sparkle sneeze). Moonshards: `fx.reveal_t0_1 = sparkles,400,195,400,1800,340,145`
(polka dots over the whole scene), `fx.reveal_t0_2 = none`, `fx.reveal_t0_3 = burst,400,170,600,600,#FFFFFF`.

A story should name every story-feature key another story uses, with `none` for an
effect it doesn't want (Moonshards' `fx.reveal_t0_2 = none`): a key missing from the
card falls back to `story_defaults.h`, i.e. to whichever story the firmware was built
with, so the card then works on either firmware.

### No big button (`nobutton.*`)

`config.ini [station] button = no|yes` says whether the plinth has a big button
(**no** is the default: in 2026 the plinth has none, and kids without a crystal tap
the screen instead). With `button = no` the firmware:

* reads **`nobutton.<key>`** before `<key>` (`settings::text`): `nobutton.caption.charge`
  replaces `caption.charge`, `nobutton.ui.or_press` replaces `ui.or_press`, and so on. A
  key without a `nobutton.` twin is used as it is. In `captions.ini` these words form the
  section `[nobutton]`, keyed `<section>.<key>`:

  ```ini
  [nobutton]
  voice = attract_call_2=attract_tap_1;charge=charge_tap
  caption.charge = TAP! TAP!
  ui.press = Tap the window!
  ui.or_press = OR TAP ME
  ```

* swaps voice per **`nobutton.voice`** = `from=to` pairs separated by `;`. Each side is a
  voice **group** id (`charge`) or a full **line** id (`attract_call_2`):
  * group = group: the firmware plays group `to` (a random variant of it) instead of group `from`;
  * line = line: when the random pick of the line's group is line `from`, it plays line `to`;
  * an empty `to` (`attract_call_2=`) never plays `from`: another variant of the same group
    is picked, or nothing if none is left.

With `button = yes` the `nobutton.*` words are ignored and the original lines and words play.

`--check` validates them like the key they replace (a `nobutton.caption.*` is held to
the caption length, a `nobutton.*_color` must be `#RRGGBB`), reports a malformed
`nobutton.voice` as an ERROR, and warns about a swap whose `from` or `to` has no lines in
the manifest, a swap listed twice, or one that mixes a group and a line. The groups named
as a `to` (Dragonglow: `attract_tap`, `charge_tap`) are accepted as voice groups even
though `cues.h` doesn't list them; they only ever play as stand-ins. A note at the end of
`--check` lists the swaps.

A card without `nobutton.*` words falls back to the ones in `story_defaults.h` (the story
the firmware was built with), so a story without stand-in lines should say
`nobutton.voice` with an empty value (no swaps) when it may run on another story's firmware.

Write the pairs without blanks. Give the stand-in lines the priority the default
station needs (Dragonglow: the tap lines are MVP and the button lines NICE), and keep
their key word first like any other line. `tools/gen_manifest_dragonglow.py` builds these
words from its `NOBUTTON_VOICE` / `NOBUTTON_WORDS` tables and refuses to write a manifest
in which a voice line or a word that says "button" or "press" has no no-button alternative.

### Tokens and the `[anchor]` section

**Tokens:** the firmware replaces `{year}`, `{next_year}`, `{rank}` and `{color}`
in a value when it shows it (e.g. `caption.goodbye` = `SEE YOU {next_year}`).
Write them exactly like that; the tool passes them through unchanged.

**`[anchor]` section (generated, not from `words`):** after the words, the build
appends one line per clip that has an `anchor_layer` and was built from real
art: `<clip id> = x,y,r` in screen pixels. That is where the firmware draws the
lantern glow in the crystal colour (`settings::text("anchor.<clip id>")`).
See `layers` → *Anchors*.

## `stills` (ChatGPT images)

Source file: `assets/source/images/<id>.png|.jpg|.jpeg|.webp`. If several exist,
the newest is used and the check warns.

| field | type | default | meaning |
|---|---|---|---|
| `id` | id | – | also the source file name |
| `kind` | `reference` `background` `character` `prop` `fx` `icon` `ui` `print` | – (required) | `reference` and `print` are never put on the card. `print` is for bowl signs and posters |
| `transparent` | bool | `false` | `true` = a sprite composited over a background. PNG/WebP alpha is used as is |
| `key` | `"auto"` / `"#RRGGBB"` / `false` | `"auto"` | colour key for transparent stills that have **no** alpha channel (see below) |
| `crop` | `center` `top` `bottom` | `center` | which part survives when a background is cropped to 5:3 |
| `priority` | `MVP` `NICE` | `NICE` (with a warning) | MVP = needed on the night |
| `desc`, `prompt` | text | | what it is, and the ChatGPT prompt |
| `used_by` | [id] | `[]` | informational. The status page also lists the clips that really use the still |
| `edit_of` | still id | | informational: this image is an edit of that one. The check verifies the id exists |
| `anchor` | `[x, y]` | none | the lantern globe (or other glow point) as fractions of the picture: `[0.5, 0.70]` = centred, 70 % down. Used by `layers` clips with an `anchor_layer` (see *Anchors*); fix it here after generating the art if the glow is off |
| `refs` | any | | informational |

`key` details:

* `"auto"` looks at the picture's four corners: a green-screen backdrop (ChatGPT's
  fallback when it can't make a transparent PNG; the story prompts ask for pure
  `#00FF00`) is keyed out; otherwise black is (ChatGPT's "isolated on flat pure black").
* `"#00FF00"` keys out a green screen.
* `false` means no keying.

Geometry:

* **Full-frame pictures**: a `background`, or any picture used as `image` or `bg`.
  * They are scaled to **cover** 800×480 (5:3) and cropped according to `crop`.
  * A 1536×1024 ChatGPT landscape loses about 5% at the top and bottom.
  * A transparent still used full-frame is fitted inside the frame and flattened onto black.
* **Sprites**: scaled to the recipe's `sprite_height`, keeping their aspect ratio and alpha.

## `clips` → `/oracle/clips/<id>.omj` (or `.jpg`)

Every clip is 800×480, baseline JPEG 4:2:0. Animated clips are OMJ1, a
length-prefixed MJPEG format described in `media.h`. Frames are built at the
clip's `fps`, and the frame count is exact.

* **Frame size:** every frame must be ≤ **96 KB**. Otherwise the clip is
  re-encoded at `q+2`, `q+4`, … up to q=12; if it is still too big, the build reports an error.
* **Variants:** a clip `<id>_<n>`, such as `reveal_t0_2`, is the picture shown with voice variant `n`.
* **Missing sources:** a clip whose source stills are missing is skipped.
  * The firmware then draws its built-in animation for the cue.
  * With `--test-clips`, a labelled test card is built instead.

Fields common to every recipe:

| field | default | meaning |
|---|---|---|
| `id` | – | a visual cue name from `cues.h` (`attract`, `chapter[_a..f]`, `absorb`, `awaken`, `greet[_r2..7]`, `recall[_t0..3]`, `charge`, `reveal_t0..3`, `bowl_*`, `replay`, `nocrystal`, `sleepy`, `foreign`, `goodbye`, `milestone`, `circle`, `keeper`, `rankup_r*`; also `attract_full` and `moonfull`, accepted even before `cues.h` defines them), optionally followed by `_1` … `_9` |
| `recipe` | – | `still`, `kenburns`, `float`, `crossfade`, `video` or `layers` |
| `priority` | `NICE` | `MVP` or `NICE` |
| `fps` | manifest `fps` | frames per second |
| `q` | 5 (`still`: 3) | JPEG quality, 2–31. Lower means better quality and bigger frames |

### `still` → `<id>.jpg`

`{"image": "<still id>"}`: a single picture. It is decoded once on the device and cached.

### `kenburns`

A slow zoom and pan over one picture. The picture is first scaled to a 3× canvas,
so even slow moves are smooth.

| field | default | meaning |
|---|---|---|
| `image` | – | still id |
| `seconds` | 4 | frames = round(seconds × fps) |
| `zoom` | `[1.0, 1.15]` | `[from, to]`, 1.0–4.0. 1 = the whole picture |
| `pan` | `center` | `center`, `up`, `down`, `left` or `right` (the direction the view travels). Any pan except `center` needs zoom > 1 at both ends |

### `float`

A sprite bobbing over a background. The loop is exact.

| field | default | meaning |
|---|---|---|
| `bg`, `sprite` | – | still ids |
| `sprite_height` | 360 | px |
| `x` | `"center"` | `"center"` or the px of the sprite's left edge |
| `y` | 40 | px of the sprite's top edge |
| `amp` | 8 | bob amplitude, px |
| `period` | 3 | bob period, s |
| `seconds` | the multiple of `period` nearest 4 s | frames = round(seconds × fps) |

* The bob is `amp · sin(2π · t / period)`.
* The clip loops without a seam when `seconds` is a whole number of periods and
  `period × fps` is a whole number of frames (e.g. 3 s at 13 fps = 39 frames).
  The check warns otherwise.

### `crossfade`

A sequence of pictures with fades between them.

| field | default | meaning |
|---|---|---|
| `frames` | – | list of `{"image": id}` (full frame) or `{"sprite": id}` (over `bg`), each with `hold` (s, default 1.0). A sprite item may set its own `sprite_height`, `x` and `y` |
| `bg` | none | background for sprite items. Sprites without a `bg` go over black |
| `fade` | 0.5 | fade length, s. 0 = hard cuts |
| `loop` | `false` | `true`: the last item fades back into the first, so the last frame leads into frame 0 |
| `float` | none | `{"amp", "period"}`: bob every sprite item, continuously across the fades |
| `sprite_height`, `x`, `y` | 360, `"center"`, 40 | defaults for sprite items |

Frames:

* hold frames H = round(hold × fps), fade frames F = round(fade × fps)
* total = ΣH + F × (number of items − 1), or ΣH + F × (number of items) with `loop`

### `video`

Any video file in `assets/source/video/`, made into a clip.

| field | default | meaning |
|---|---|---|
| `source` | – | file name in `assets/source/video/`. Without an extension, any video type with that stem is found |
| `start` | 0 | s into the source |
| `seconds` | to the end | length |
| `crop` | `center` | `center`, `top` or `bottom` (cover-crop to 5:3) |
| `denoise` | `"4:3:8:6"` | hqdn3d parameters, applied before the colour conversion. `false` = off. AI video is grainy, and grain makes frames big |
| `loop_fade_frames` | 0 | K > 0: the clip's last K frames crossfade into its first frames. The result is N − K frames that loop without a seam |

### `layers`

A timeline: a background plus stills drawn on top of it in list order, each
with its own visible window, keyframed size/position/rotation, fades and
effects. One ffmpeg filter graph builds the whole clip, so the frame count is
exact: **frames = round(seconds × fps)**, and frame *n* is at **t = n / fps**.
All times are clip seconds.

```json
{"id": "reveal_t2", "recipe": "layers", "seconds": 2.5, "loop": false,
 "bg": {"image": "bg_awaken"},
 "layers": [
   {"sprite": "oona_surprise", "height": 300, "x": 400, "y": 50, "bob": {"amp": 6, "period": 2.4}, "fade_in": 0.15},
   {"sprite": "prop_witchhat", "height": [60, 150, 150], "x": 400, "y": [260, 95, 105],
    "t": [0.2, 2.5], "fade_in": 0.15, "spin": 1.5}],
 "anchor_layer": 0}
```

Clip fields:

| field | default | meaning |
|---|---|---|
| `seconds` | 4 | 0.1–60. frames = round(seconds × fps) |
| `loop` | `false` | `true`: the clip repeats. The check warns when frame N (the one after the last) would not equal frame 0 - a bob whose period doesn't divide the length, a layer visible only at one end, or a background zoom/rotation |
| `bg` | black | `{"image": id, "zoom": [from, to], "rotate": [fromDeg, toDeg], "fallback": id}`, or just a still id |
| `layers` | – | list, drawn in this order (later = in front) |
| `anchor_layer` | none | index into `layers` of the sprite carrying the lantern (see *Anchors*) |
| `variants` | none | `"colors"`: also build `<id>_1` … `<id>_N`, one per **defined** crystal colour (N = the colour count, see *Crystal colours*; 3 in Dragonglow), each with every `"$color"` tint replaced by that colour's spec `words` `color.N_hex`. The plain `<id>` is built untinted (a crystal with no colour). Old `<id>_N` placeholder/test outputs above the count are deleted by the next build; real ones are listed as orphans |

`bg`:

* `image`: a full-frame still, cover-cropped to 800×480 like every background.
* `zoom`: a slow centred Ken Burns, from → to over the clip (1.0–4.0, worked on a 3× canvas so slow moves don't step).
* `rotate`: the background turns from → to degrees (−45…45) over the clip. A
  larger-scaled copy is rotated, so no corner ever shows (15° zooms in about 1.4×).
* `fallback`: used when `image` has no source yet. Without both, the clip isn't built.

Each layer has exactly one of:

* `sprite`: a cut-out still (`"transparent": true`; PNG/WebP alpha, or a keyed green-screen / black backdrop - see `key`).
* `image`: a full-frame still (cover-cropped), e.g. the lit hillside fading in over the dark one.

Layer fields (*keyframes* = a number, or a list of numbers spread evenly
across the layer's window and interpolated linearly between neighbours;
before/after the window the first/last value holds):

| field | default | meaning |
|---|---|---|
| `height` | 360 | sprite height in px (keyframes). Width follows the picture's aspect ratio |
| `x` | `"center"` | the sprite's **centre** x in px (keyframes), or `"center"` (= 400) |
| `y` | 40 | the sprite's **top** y in px (keyframes) |
| `t` | `[0, seconds]` | `[start, end]`: the visible window in s. It may run past the clip's end (keyframes and fades still use the whole window) |
| `fade_in`, `fade_out` | 0 | alpha fades in s, at the start / end of the window |
| `bob` | none | `{"amp": px, "period": s}`: y += amp · sin(2π · t / period), t = clip time, so consecutive layers bob in step |
| `flutter` | `false` | wing flutter: width × (1 ± 0.03) at 6 Hz |
| `rotate` | none | degrees, clockwise (keyframes). Corners stay transparent |
| `spin` | none | full horizontal turns over the window, like a coin: width × max(0.08, \|cos(2π · spin · progress)\|). Whole or half-whole numbers end facing front (1.5 = three edge-on moments) |
| `tint` | none | a colour spec (`"#RRGGBB"`, `"#RRGGBB,#RRGGBB[,..]"` with 2–4 stops, or `"rainbow"`; see *Crystal colours*): multiply-tint for near-white art, keeping highlights (75 % multiplied + 25 % original). One colour tints evenly; stops and `rainbow` tint a gradient across the sprite box (t = 0.8 · y/h + 0.2 · x/w: first stop at the top, last at the bottom, a slight diagonal). Alpha is kept. Applied once, after the sprite is scaled to its (largest) `height`. `"$color"` = the crystal colour spec of each `variants` clip |
| `blend` | `"normal"` | `"screen"`: lighten-only, for glows and bubbles drawn on black |
| `optional` | `false` | `true`: a missing still skips this layer instead of blocking the clip |
| `fallback` | none | a still to use when this layer's still has no source yet |

`height`, `x`, `y`, `rotate`, `spin`, `flutter`, `bob` and `tint` do nothing on an `image` layer.

**Missing sources.** A clip is built when its background and every
non-optional layer have a source (their own or their `fallback`). Otherwise the
firmware draws its procedural fallback for the cue (`--test-clips` builds a test card instead).

**Anchors.** For a clip with `anchor_layer`, the build computes where that
sprite's still `anchor` (`[fx, fy]` of the picture) lands on screen at the
layer's first visible moment (its window start, or 0), ignoring `bob`: x = layer
centre + (fx − 0.5) × width, y = top + fy × height (rotated with the layer if
it is rotated), and a glow radius r = 11 % of the layer height (at least 18 px).
Every built clip with an anchor gets a `captions.ini` `[anchor]` line
`<clip id> = x,y,r`, including colour variants (`awaken_3`) and voice variants
(`reveal_t0_2`). A still without `anchor` uses its centre. A fallback still uses its own `anchor`.

**Previews.** After a build, `assets/previews/<id>.jpg` shows each clip built
from real art as a 2×2 sheet (frames at 10/35/60/85 %, half size) with the
anchor marked by a cyan ring; `assets/previews/index.html` lists them. Check
the glow position there before taking the card to the screen.

## `voice` → `/oracle/voice/<id>.wav`

Source file: `assets/source/voice/<id>.wav|.mp3|.m4a|.ogg|.flac|.aac`.

| field | type | meaning |
|---|---|---|
| `id` | `<group>_<n>` | n = 1…9 |
| `group`, `variant` | | optional. If given, they must match the id |
| `speaker` | text | who says it |
| `text` | text | the line. It is also what the placeholder TTS speaks |
| `caption` | text | short subtitle (reference; the screen shows `caption.<cue>` from `words`) |
| `delivery` | text | acting note |
| `priority` | `MVP` / `NICE` | |
| `fx` | `"smudge"` | a voice effect applied before loudness normalisation: `smudge` pitches the recording up 5 semitones at a net 1.15× speed (a sidekick's lines recorded in the narrator's voice: Smudge in Moonshards, Snuffwick in Dragonglow). Also applied to TTS placeholders |

**Groups** are the cue groups in `cues.h`:

* `attract_call`
* `chapter_a` … `chapter_f`
* `awaken`, `awaken_a`, `awaken_b`, `awaken_c` (in the story, `awaken_b`'s variant = the crystal colour id)
* `greet_r2` … `greet_r7`
* `recall_t0` … `recall_t3`
* `charge`
* `reveal_t0` … `reveal_t3`
* `bowl_common`, `bowl_rare`, `bowl_legend`
* `replay`, `nocrystal`, `foreign`, `sleepy`, `goodbye`, `milestone`, `circle`, `keeper`
* `rankup_r2` … `rankup_r7`
* `rush_t0` … `rush_t3`, `moonfull_a`, `moonfull_b`: played by the story firmware.
  They are accepted whether or not `cues.h` defines `RUSH` / `MOONFULL` yet.
* `awaken_b_1` … `awaken_b_<count>` are colour-indexed: the number is the crystal colour (`color.N`), not a random pick. Give every defined colour one line (Dragonglow: `awaken_b_1..3`); a line above the colour count never plays (`--check` warns).

* any group named as a stand-in (`to`) in the words `nobutton.voice` (Dragonglow:
  `attract_tap`, `charge_tap`), played instead of a button line when the station has no
  big button (see *No big button*).

A group that is not in this list is an error, unless `extra_voice_groups` names it.

**Number variants from 1 with no gaps.** The firmware stops counting at the
first missing number, so the check warns about lines that would never play.

## `sfx` → `/oracle/sfx/<id>.wav` and `music` → `/oracle/music/<id>.wav`

Source file: `assets/source/sfx/<id>.*` or `assets/source/music/<id>.*`, in the same formats as voice.

| field | meaning |
|---|---|
| `id` | the firmware loads these sound effects: `absorb`, `awaken`, `reveal_t0..3`, `tap`, `charge_full`, `sleepy`, `button`, `whoosh`, plus `munch`, `milestone`, `moonfull`. Any of them may carry a variant suffix `_1` … `_9` (`reveal_t0_2` = the 2nd trick gag's sting). For music it loads `idle` and `idle_full` (looped). Any other id gives a warning: it is built but never played |
| `synth` | placeholder recipe (see below) |
| `seconds` | placeholder length (each synth has its own default) |
| `priority`, `desc` | |
| `_search` | free text: search words for the sound libraries, shown in CHATGPT-ASSETS.md |

The `synth` placeholder recipes:

* `rise`: rising shimmer
* `sparkle`: random high pings
* `chime`: bell
* `fanfare`: arpeggio and chord
* `wahwah`: sad trombone
* `blip`: tap
* `bloop`: falling blip
* `whoosh`: filtered noise sweep
* `drone`: low eerie pad that loops without a seam (music)

Without a `synth`, a default is picked by id.

## Audio format (all categories)

* RIFF WAV, PCM s16le, mono, 48000 Hz, with the canonical 44-byte header. The
  tool checks the header byte by byte.
* Loudness: voice and sfx −16 LUFS, music −20 LUFS (true peak −1.5 dBTP, LRA 11).
* Filtering: 120 Hz high-pass for the small speakers, and 5 ms fade-in and fade-out.
* Voice lines get two extra steps:
  * Silence at the start and end is trimmed: below −50 dB, keeping 40 ms of
    lead-in and an 80 ms tail.
  * A gentle 3:1 compressor runs above −20 dBFS, so short lines reach −16 LUFS.
* Placeholder TTS lines also have pauses longer than 0.25 s squeezed to 0.2 s.
